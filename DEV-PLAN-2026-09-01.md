# MWGym Dev Plan — One Canonical WorkerRun

**Date:** 2026-09-01
**Goal:** One scientifically valid learning loop from Oracle opportunity → WorkerRun → verifier → learning → improvement.

## The Problem

The pieces are ~70% there. The actual feedback loop is ~30% there. The latest run proved the data pipeline works (103 runs, 50 trajectories, 51 graph edges, 4 insights) but the learning wasn't real — capability scoring was heuristic, verifiers were stubs, and the worker output was never applied into CGE state before scoring.

## What We're Building

One canonical exemplar: **API rate limiter**.

```text
Oracle Opportunity EX-API-001
        ↓
Frozen WorkOrder
        ↓
Worker v1 (baseline)
  - fresh Git worktree (B0)
  - PydanticBATS bounded execution
  - Deterministic verifier
  - B1 commit
  - WorkerKit receipt
  - Hydra projection
        ↓
Training on CGE sibling worlds
  - 20 frozen worlds (train/dev/sealed)
  - Each produces a WorkerRun
  - Failures → adversary → next world
        ↓
Every ~10 runs: Letta reflect
  - Trajectories + Hydra summary
  - Proposes one memory/skill/process change
  - Candidate branch in Git
        ↓
Incumbent vs Candidate on held-out DEV worlds
  - Replace-if-wins (real improvement only)
        ↓
At 100 runs: sealed evaluation
  - v1 vs vN on unseen worlds
  - Full report: quality, cost, latency, capabilities
```

## Implementation Steps

### Step 1: WorkerRun spec (spec.py)
The canonical data object. Everything converges here.

### Step 2: Deterministic verifier (verifier.py)
Real tests for the rate limiter. No LLM judges. Gate results → capability scores → FailureVector.

### Step 3: Fix CGE scoring
Apply worker output into CGE state BEFORE scoring. Currently scoring the empty world.

### Step 4: Fix Git ownership
Orchestrator owns B0/B1. Harness doesn't touch Git.

### Step 5: Campaign runner
One script that runs the full loop: exemplar → training → reflection → candidate → held-out → report.

### Step 6: Get Letta live
Runtime-letta service needs to be running for the persistent planning role.

### Step 7: Run the real loop
Execute and produce the v1 vs vN comparison.

## Key Architecture Decisions

- **LETTA** = persistent brain (planning, memory, reflection)
- **PYDANTIC** = fast executor (bounded, cheap, tools)
- **HYDRA** = empirical record (what happened)
- **CGE** = school (next useful lesson)
- **GIT** = genome substrate (version everything)
- **WORKERKIT** = witness (prove everything)
- **VERIFIER** = sovereign truth (no LLM judges)
